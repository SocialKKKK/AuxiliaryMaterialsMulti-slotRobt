## 3. 仍可复现的问题

### P1：同秒记录被一起回填

`app.operation_log.backfill_door_ts` 仅用 `(action_type, ts)` 定位，时间精度为秒。两格同秒开门，第一格关闭后两条记录都写成第一格的关门时间；第二格真正关闭时无法再补。`RowsAffected > 1` 的检查在 UPDATE 完成后发生，没有回滚；触发器随后禁止更正已填的值。

复现：两条 `mh_take_wire`，分别 F-A01/F-A02，`ts=2026-10-09 10:00:00 UTC`；分别传入关门 `10:00:05`、`10:00:10`。

```text
F-A01 door_close_ts = 10:00:05 UTC
F-A02 door_close_ts = 10:00:05 UTC
firstSuccess=False, secondSuccess=False
```

应使用稳定动作 ID 关联写入、待补偿、回填；即使暂用复合键，也必须涵盖格口并在写入前保证唯一，不能更新多行后才报告失败。

### P1：待补偿回填写失败仍返回成功

`OperationLogPendingStore.TryPatchDoorTs` 调用 `Write` 后直接返回 true；`Write` 丢弃 `DbResult`，未检查 `HasError/RowsAffected`。数据库更新失败或与重试并发导致影响 0 行，都可能误报成功。

复现：业务 INSERT 故障入队；临时触发器拒绝队列 `entry_json` 更新。

```text
reportedSuccess=True, storedClose=NULL
```

应检查更新结果，并与重试读取/补写共享同步或事务保护。若重试已先落库，应重新对原记录幂等回填。

### P2：已落库记录的回填 SQL 失败没有补偿任务

当前只处理「UPDATE 正常执行且命中 0 行、原记录还在队列」；如果 UPDATE 本身 `HasError`（缺条目、锁超时、写失败），直接失败返回，不创建回填补偿任务。MH 关门通知移除内存关联后也不再重试；OP 仅告警。

复现：原业务记录已落库，临时触发器拒绝记录 UPDATE。

```text
success=False, pending=0
```

告警可见不等于可恢复；需要保存后到的门时刻及动作关联，并在故障恢复后重试。

### P1：MH 中断仍可能没有存取记录表留痕

实跑 mock `material_handler_load_available_wire` 至 `closeAvailableSlotDoor`：`openAvailableSlot` 成功，持久记录为 0。业务记录要等关门后的 `updateDB` 才写。此间若崩溃或终止，`FlowCoordinator.EndFlow` 只释放 runner，巡检也不为未跟踪的流程开门补记录。

完整 HMI 已有 `MhInterruptedLoadStore` 独立中断快照和启动提醒；不能称为「完全没有故障信息」。但该表只有可覆盖的一行，不含完整操作人/门时刻，也不进入存取记录查询与导出。上述 mock 复现只覆盖 FlowEngine，未模拟完整 HMI 崩溃与启动；记录表的缺口由路径核对确认，完整恢复行为仍需测试。

应让未完成动作可在存取记录里追溯；中断提醒不能替代记录表的历史留痕。
