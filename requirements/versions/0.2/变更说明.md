## 2. 新增

### 2.1 功能

- 任一存取动作（存料 / 归还 / 领用 / 取出 / 开门 / 试开 / 控车回充 / 失败 / 无指令开门）**自动写入一条记录**，一次业务操作一条。
- 「物料存取记录」页签：六项条件组合查询、时间倒序、每页 20 条。
- **按批号追溯全程**：入库 → 在柜 → 归还 → 被取走。
- **导出 Excel**（本地目录 / U 盘），权限限物料员与维护人员。
- **写入失败补偿**：不阻断业务 + 告警 + 自动重试 + 待补偿列表。

详见 [需求范围 §3](需求范围.md)。

### 2.2 应用库

- 表：复用 `app_operation_log`（0.1 已建表、**全工程零代码引用**，因此扩列不影响任何既有逻辑）。
- 既有列保留不动：`id / ts / operator_id / flow_id / node_id / slot_no / lot_no / message / mes_result / lock_result / error_info`。
- 新增列 15 个，见 §5.2。
- 新增索引：`ts`、`lot_no`、`slot_no`、`operator_id`、`eqp_no`。

### 2.3 SQL catalog

在 `requirements/data-access-sql/sql-catalog/items/` 新增（并同步 `index.yaml`）：

| sql_id（拟） | 用途 | 操作 |
|---|---|---|
| `app.operation_log.insert` | 写入记录 | write |
| `app.operation_log.list_by_filter` | 六项条件组合查询（分页） | read |
| `app.operation_log.list_for_export` | 导出取数 | read |
| `app.operation_log.timeline_by_lot` | 按批号取全程时间线 | read |
| `app.operation_log.mark_access`（可选） | 查看 / 导出行为留痕 | write |

### 2.4 界面

- 权限复用既有密码门禁 `MaintAccessGate` / `MhAccessGate`。

## 5. 数据库升级（**本版本最需要注意的一项**）

### 5.1 问题

`scripts/schema.sqlite.sql` 全部使用 `CREATE TABLE IF NOT EXISTS`（第 3 / 24 / 34 / 48 / 60 行），而 `SqliteDb.Initialize`（`src/WireCabinet.Data/Data/SqliteDb.cs`）只是顺序执行建表与种子脚本，**没有列级迁移**。

因此：**现场已存在的 `data/app.db` 不会因新脚本而获得新列**。若只改建表语句，现场升级后代码访问新列会直接报错（no such column）。

### 5.2 新增列清单（`app_operation_log`）

| 列 | 类型建议 | 说明 |
|---|---|---|
| `operator_name` | TEXT | 操作人姓名 |
| `operator_team` | TEXT | 班组 |
| `operator_role` | TEXT | MH / OP / MAINT |
| `action_type` | TEXT | 动作类型（见 §3.1） |
| `wire_spec` | TEXT | 焊丝规格 |
| `eqp_no` | TEXT | 机台号 |
| `product_lot_no` | TEXT | 产品批次号 / 领用工单批次号 |
| `qty` | REAL | 数量 |
| `remain_qty` | REAL | 剩余数量 |
| `station` | TEXT | 作业站点 |
| `result` | TEXT | 成功 / 失败 |
| `door_open_ts` | TEXT | 格口开门时间 |
| `door_close_ts` | TEXT | 格口关门时间 |
| `is_cleared` | INTEGER DEFAULT 0 | 「开门即清空」标记 |
| `is_uncommanded` | INTEGER DEFAULT 0 | 「无指令开门」标记 |

### 5.3 迁移方案

沿用工程内**既有模式**：`EnsureColumn`（`src/WireCabinet.Hmi/Services/MhInterruptedLoadStore.cs:128`）——先 `PRAGMA table_info(表)` 判断列是否存在，不存在再 `ALTER TABLE ... ADD COLUMN`，幂等可重复执行（既有用例见同文件第 43、44 行；另见 `src/WireCabinet.Data/Mes/WireMesDiscoSchema.cs:95`）。

要求：

- 新增 `app_operation_log` 的列迁移逻辑，**幂等**，可重复执行不报错。
- 迁移在应用启动时执行，先于任何记录写入。
- 建表脚本（`schema.sqlite.sql`）**同步补上新列**，保证全新库一次建对，与迁移逻辑并存不冲突。
- **只加列**：不修改、不删除 `app_operation_log` 的任何既有列，也不改动既有数据。

### 5.4 建议的数据库配置调整（非验收项，但强烈建议）

记录写入会与既有写入者竞争**同一个 SQLite 文件**：硬件轮询约 **2s**（`Hardware:HealthCheckIntervalMs`，其回调会跑门态对账并可能写库）、AGV 背景轮询 **5s**（`Agv:RecommendedPollIntervalMs`）、MES 对账重试 **2min**。

当前连接串仅有一个 `DataSource`（`src/WireCabinet.Data/Data/SqliteDb.cs`），**未开 WAL、未显式设 `busy_timeout`**。并发写不会立刻报错，但可能阻塞到默认超时，表现为**界面卡顿**而非异常——这类问题最难排查。

建议（**仅改连接串 / 连接初始化，不触碰任何业务逻辑**）：

| 措施 | 作用 |
|---|---|
| 开启 WAL（`journal_mode=WAL`） | 读写不互斥，显著降低与既有轮询的争用 |
| 显式设置 `busy_timeout` | 明确等待上限，避免默认 30s 的长阻塞 |
| 记录写入采用**排队 + 单写通道**，业务线程不等待 | 写入永不阻塞业务流程 |
| 为 `ts / lot_no / slot_no / operator_id / eqp_no` 建索引 | 日志表增长后不影响**共用同一库文件**的既有查询 |

若不做上述调整，验收时须重点关注 [验收清单 §9](验收清单.md) 的 C4（批量开格口耗时对比）。

## 7. 回滚方式

- **功能回滚**：停用「物料存取记录」页签入口 + 停止写入挂接即可，其余功能不受影响。
- **数据库回滚**：新增的 15 列**无需删除**。旧代码不引用 `app_operation_log`（0.1 全工程零引用），多出的列不会影响既有查询与写入。
- 记录表为**只增不改**，回滚不产生数据不一致。
