# 控车充电阻塞排查与修复（2026-10-08）

现场反馈：车辆停在充电桩，HMI 无法操控，需要进入 ROIT 才走。未取得故障当时的现场快照，因此下面的代码缺陷已确认，现场本次命中的具体路径尚未确认。

## 1. 与存取记录、阈值的关系

- HMI 的 IDLE 限制来自 `143f531`（2026-06-05），订单门禁及返航阻塞来自 `fc42500`（2026-07-02），均早于存取记录功能。
- 9 月新增记录时没有改变充电离站规则；没有证据表明这次故障由记录功能造成。
- 9 月 29 日保存的现场配置是 30% 回充、90% 返航；用户确认以前也是该配置。快照仅用于确认保存值，不表示阈值在那天被修改。
- 仓库共享配置的 41%/43% 是旧默认值，不能据此推断现场生效值。本次不修改任何电量阈值或现场配置。

## 2. 修复前的代码问题与复现

0.1 需求 §7.2 要求充电中允许控车，业务策略也放行充电态，但 HMI 和订单门禁仍要求 IDLE。
用内存客户端调用产品类，电量 100%、位于充电点、在线、格口全关、移动/进程就绪、无订单、已登记返航：

| 状态 | 修复前手动发车 | 修复前自动返航移动接口次数 |
|---|---|---|
| CHARGING | 拒绝（仅 IDLE） | 0 |
| IDLE | 允许 | 1 |

因此达到 90% 并不保证旧程序能返航；9 月 29 日成功返航只证明当时最终具备发车条件。
另有充电单不能取消、本地 pending 状态异常静默阻塞、外部充电只在启动时识别、UI 必须观察过活动订单才解锁等路径。
最初复现资产在 `%TEMP%\wirecabinet-charge-diagnosis-20261008\`，它记录修复前行为；修复后的证据以新增产品测试为准。

## 3. 本次修复（用户已要求修复，尚未部署）

| 路径 | 当前处理 |
|---|---|
| 手动充电离站 | 与控制循环统一：充电态无订单时可发移动单，但仍检查在线、急停、移动/进程就绪、门全关、开锁互斥、订单互斥 |
| 有充电任务 | 仅当本车活动订单的 mission 同时匹配配置的充电目的地和动作 ID，才请求取消；保留所选站点，等 RCS 快照确认订单释放后派车，不提前发移动单 |
| 等待期间 | 不重复取消/下单；取消按钮可以撤销待离站请求；手动目标优先于默认返航 |
| 自动返航 | 达到原有返航阈值后复用同样门禁；有已识别充电单时先请求取消，等释放后返航 |
| 外部充电 | 周期性在进入充电/充电点的状态迁移时登记返航，优先此前作业站，否则默认物料间；不在每个 tick 重复登记 |
| 本地 pending | 兼容 `doneTime` / `done_time`；取消状态或完成时间确认终态。详情查询失败显示原因并保留联锁；车辆订单为空不代表队列单完成 |
| 缺失订单号 | 返回成功却无订单号时保留确认联锁，防止重复下单 |
| UI 移动锁 | 依据请求/订单已结束及允许再次发车解锁，不再依赖曾观察过活动订单 |
| 自动路径联锁 | 回充和返航也检查门全关、未知门态及开锁中；不放宽门禁 |
| 并发与错误 | HMI 手动命令、连接/刷新及后台轮询串行；刷新失败暂停下单并给出原因；启动不再盲目取消 IDLE 下的排队订单 |
| RCS 响应 | HTTP 200 中的非零业务 code 也视为失败；无效订单详情不当作有效空订单 |

不猜测未确认的完成状态码：`CompletedOrderStates` 默认空，只有确认 RCS 实际完成码后才配置。
不修改物料流程定义、应用库 SQL、记录写入机制或密码配置。
