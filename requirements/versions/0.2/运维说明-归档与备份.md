# 0.2 运维说明：物料存取记录的归档与备份

本文件支撑 [验收清单 §6 数据验收](../0.2/验收清单.md) 的「永久保留」与交付物清单中的
「归档策略（周期、存放位置）」与「备份策略」。

> 状态：**技术事实与可执行做法已确定；周期、存放位置、责任人需现场确认后冻结**（见 §5）。
> 带 ⚠ 的条目是现场验收前必须填实的内容。

---

## 1. 事实基础

| 项 | 现状 |
|---|---|
| 存储 | 柜端 SQLite，`requirements/versions/0.1/wire-cabinet/data/app.db`（单文件） |
| 记录表 | `app_operation_log`，**业务事实不可改写**；产品禁止 DELETE，UPDATE 只放行补 NULL 门时刻与更新派生 `detail`。现有库触发器仅保护 UPDATE，没有 DELETE 触发器 |
| 待补偿队列 | `operation_log_pending`（写入失败转存，补写成功后置 `success` 保留留痕） |
| 并发写入者 | 硬件轮询约 2s、AGV 轮询 5s、MES 对账重试 2min，**与记录写入共用同一个库文件** |
| 日志模式 | **已开 WAL**（每次启动设置一次）+ 忙等待上限 15s（见 变更说明 §5.5） |
| 实测规模 | 演示数据 16 行时库文件约 120 KB（含 54 格口与 53 条焊丝规格等既有数据；记录表本身占比很小） |

**增长量级估算**：记录表的行数由业务操作次数决定，不随时间自然增长（控车/回充只在状态迁移时记一条，
静置不产生记录——验收 C5 有用例钉住）。按单班数百次存取操作、每行约 300～500 字节估，
一年约数十万行、十几到几十 MB 量级。⚠ 现场按实际班次与操作频次复核。

## 2. 归档策略

**原则：归档后不删除**（需求方同时要求「永久保留」与「需要归档或定期清理」，已按决议 3 定为
「永久保留 + 归档但不删除」）。

推荐做法（按年归档）：

1. **按年导出**：每年初用「存取记录」页签把上一年的记录导出为 Excel，导出前把时间范围设为完整年度，
   文件命名 `物料存取记录_YYYY.xlsx`，存 ⚠（待定：归档目录 / 移动硬盘 / 文件服务器）。
2. **保留原件**：归档**只导出不删除**，`app_operation_log` 中的记录保持不动。
   若日后确认需要「按年分表」，须先与需求方书面确认——那会改变「记录只增不删」在 DB 层的形态。
3. **归档校验**：导出后核对文件行数与筛选条件下的记录数一致（页签上有条数提示；
   Excel 末行号 − 1 即行数）。

周期：⚠ 待定（建议每年一次；也可按现场盘点周期，如每半年）。

> 不做的事：**不给记录表加删除入口、不做自动清理**。需求方虽勾选了「需要归档或定期清理」，
> 但决议 3 已明确「归档后不删除」，且验收 §10 把「记录可被修改或删除」列为未通过条件。

## 3. 备份策略

备份的是**整个 `app.db`**，不只是记录表——记录与其他业务状态在同一文件里，单独备份记录表反而会造成不一致。

| 项 | 建议 | 备注 |
|---|---|---|
| 方式 | 停止程序后复制 `data/app.db`（**推荐**）；或使用 SQLite 在线备份（`VACUUM INTO`） | ⚠ 直接复制正在运行的库文件可能拿到不一致快照。已开 WAL，库目录会多出 `app.db-wal` / `app.db-shm`，**不要只拷这两个**（它们是运行期附属文件，单独拷没有意义） |
| 频率 | 每日一次（班后）+ 每月归档一份 | ⚠ 待定 |
| 保留份数 | 至少保留最近 7 份日备 + 全部月备 | ⚠ 待定 |
| 存放 | ⚠ 与柜体不同的物理介质（U 盘 / 文件服务器 / 移动硬盘） | 与柜体同盘备份无法防硬件故障 |
| 校验 | 备份后能在另一台机器上用 SQLite 打开并 `SELECT COUNT(*) FROM app_operation_log` | 只检查文件存在不算校验 |
| 责任人 | ⚠ 待定 | |

### 3.1 恢复步骤

1. 停止程序（`WireCabinet.Hmi` 进程退出）。
2. 把备份的 `app.db` 覆盖到 `data/app.db`（先另存现场文件，避免覆盖出错无法回退）。
3. 启动程序。启动时会自动执行幂等迁移（补列、建 MES mock 表、补演示数据），**不需要**手工跑脚本。
4. 打开「存取记录」页签抽查：条数与备份时点一致、时间倒序正常。

> 注意：**恢复会连带回退其他业务状态**（格口绑定、待补偿队列、MES 同步状态），不只是记录。
> 这一点在恢复前必须让现场知悉。

## 4. 与「永久保留」的关系

- 记录的永久保留由**本地库 + 定期备份 + 按年归档**三者共同满足（决议 2、3）。
- 不做服务器/集中式数据库（决议 2），因此**没有**跨柜汇总、也没有集中归档。
- ⚠ 若需求方日后要求「跨柜可查」，那属于 0.2 明确不做项（[需求范围 §7](../0.2/需求范围.md)），需另行立项。
