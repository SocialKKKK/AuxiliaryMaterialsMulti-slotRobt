# 0.2 版本需求范围

## 1. 版本定位

0.2 是 0.1 之后的第一批增量。当前仅包含一项已确认需求：**物料存取记录与追溯**（需求方亦称「存取焊丝记录」「操作日志」）。

该功能在 0.1 需求文档中**已列出但未实现**（[../0.1/需求范围.md](../0.1/需求范围.md) §2.1 界面清单「操作日志查看或导出」、§4.3 操作日志表）；0.1 因范围冻结未做，0.2 按需求方 2026-09-22 确认口径补做并扩展。

需求来源与确认过程见 [物料存取记录-需求确认清单.md](物料存取记录-需求确认清单.md)（含需求方逐项勾选原文与 5 条决议）。

### 1.1 主链路

```text
任一存取动作发生（存料 / 归还 / 领用 / 取出 / 开门 / 试开 / 控车回充 / 失败）
    → 自动向应用库写入一条记录（一次业务操作一条）
    → 「物料存取记录」页签按条件查询（时间 / 批号 / 格口 / 操作人 / 机台 / 动作类型，可组合）
    → 按批号查看该卷焊丝全程时间线（入库 → 在柜 → 归还 → 被取走）
    → 导出 Excel（本地目录 / U 盘）
```

### 1.2 设计原则

- 不在 0.1 既有链路上做破坏性改动：**记录写入失败不得阻断业务操作**。
- 记录**只增不改不删**；查看与导出行为本身也留痕。
- 记录功能**独立于** MES 对账界面，不并入。
- 应用库仍为**柜端 SQLite**，不引入服务器数据库。
- 查询口径以**按批号追溯全程**为主，不做按时间/人员的统计报表。

### 1.3 与 0.1 的关系

| 项 | 0.1 现状 | 0.2 处理 |
|---|---|---|
| 应用库 `app_operation_log` 表 | 已建表（`scripts/schema.sqlite.sql`） | 扩字段，不改既有列 |
| `agv_move_log` 表 | 已建表 | 保留，用于控车过程明细（见 §3.1 设计取舍） |
| 0.1 的 6 条焊丝流程 | 已实现 | **不修改流程定义**，仅在节点成功后挂接写入 |
| 0.1 的 MES 对账界面 | 已实现 | 不改动，新功能独立 |
| 顶栏 5 个页签 | 已实现 | 新增第 6 个页签（见 §6） |

### 1.4 非侵入性约束（硬性）

本功能**不得影响 0.1 既有功能的使用**。为此约定：

1. **记录写入不参与业务判定**：写入失败不得改变任何流程节点的 outcome 或路由，也不得与业务写入放在同一事务中；异常必须被隔离并转入告警 / 重试通道。
   > ⚠ `FlowEngine` 内既有的 DISCOEQPNO 同步挂接位于**同一位置**，其失败会把 outcome 改为 `error`。记录写入**不得**沿用该写法。
2. **只加列，不动既有列**：`app_operation_log` 仅新增列，不修改、不删除既有列（该表在 0.1 全工程零引用，扩列对既有逻辑无影响）。
3. **不新增 MES 调用**：记录所需字段（操作人姓名、规格、机台等）复用流程内**已有**的 MES 查询结果。
4. **不按轮询 tick 记录**：控车与回充**仅在状态迁移时**落库，不得每个轮询周期写一条。
5. **不改变既有轮询节奏**：记录页刷新不得叠加到既有 2s（硬件轮询）/ 5s（AGV 轮询）/ 2min（MES 对账重试）之上。
6. **关闭即可复原**：停用页签入口与写入挂接后，0.1 能力不受任何影响。

约束的验收方式见 [验收清单 §9](验收清单.md)。

## 3. 功能需求

### 3.1 记录范围

| # | 动作 | 触发点 | 备注 |
|---|---|---|---|
| 1 | MH 存入可用焊丝 | 存料流程 `updateDB` / `app.slot.bind_wire` 成功后 | 需含焊丝型号、批号、存储格位、时间 |
| 2 | OP 归还旧焊丝（退料提交） | `submitWireReturn` 成功后 | |
| 3 | OP 领用新焊丝（领用提交） | `submitWireIssue` 成功后 | |
| 4 | **OP 从格口取出焊丝** | 取出动作完成、关门后 | **单独一条**，不与第 3 项合并；记录该格**开门时间与关门时间** |
| 5 | MH 打开单个 / 批量打开格口 | `MhDoorOnlyService` 每次开锁成功后 | 维护动作，不涉及库存变化但需留痕 |
| 6 | 维护人员试开单个格口 | 维护视图试开成功后 | 需要留痕 |
| 7 | **操作失败** | 各动作的失败分支 | **不作为一种动作类型**（见下方设计说明） |
| 8 | AGV 控车与自动回充 | 下单 / 暂停 / 继续 / 取消 / 回充 / 返航 | 客户明确要求记录 |
| 9 | 格口开关记录 | 开门 / 关门事件 | 开门和关门分别追加一条，均可查询 |
| 10 | **无指令开门**（计划外释锁） | 门态监测发现库内无开门指令而 DI 显示释锁 | 客户要求「记录无指令开门，方便确认原因」 |

**设计说明（开发方解释，可调整）**

1. **第 7 项「操作失败」不单独作为动作类型**：失败是任一动作的结果，实现为同一条记录的 `result = 失败` + `error_info` 填写失败原因。这样一次失败只产生一条记录，符合「一次业务操作记一条」。
2. **第 8 项控车记录的归属（设计取舍）**：为保证按批号 / 格口 / 时间**统一查询**，AGV 控车与回充动作**也写入同一张记录表**（用 `action_type = agv_move` / `agv_charge` 区分）；既有的 `agv_move_log` 保留用于控车过程明细，两者不冲突。
3. **第 9 项**按事件分别记录开门和关门；关门事件可带同格的开门时刻，开门记录不回写。**第 10 项**复用开门类型，以 `is_uncommanded` 标记表达。

### 3.2 记录粒度

**一次业务操作记一条。**

- 一次完整的「存废取新」，按段记：归还 1 条、领用 1 条、取出 1 条。
- 一次批量开格口，**每个成功开门的格口各记 1 条开门事件，确认关门时再各记 1 条关门事件**。
- 存料、归还、领用、取出等业务动作各自记录；相关格口的开门和关门另按事件记录。
- 不做「每个流程节点一条」的细粒度流水。

### 3.3 记录字段

| 字段 | 取值来源 | 说明 |
|---|---|---|
| 时间 `ts` | 原动作发生时刻（补偿写入仍保留原时间） | 既有列 |
| 操作人工号 `operator_id` | 表单 / MES 校验结果 | 既有列 |
| 操作人姓名 `operator_name` | MES `mes.operator.get_by_id` | **新增** |
| 操作人班组 `operator_team` | 表单输入 | **新增** |
| 操作角色 `operator_role` | MH / OP / MAINT | **新增** |
| 动作类型 `action_type` | 见 §3.1 | **新增** |
| 格口编号 `slot_no` | 格口 | 既有列 |
| 焊丝批号 `lot_no` | 表单 / MES | 既有列 |
| 焊丝规格 `wire_spec` | MES `mes.wire.get_by_lot_no` | **新增** |
| 机台号 `eqp_no` | 表单 / MES | **新增** |
| 产品批次号 `product_lot_no` | 归还段自动查询 / 领用段手工输入 | **新增** |
| 数量 / 剩余数量 `qty` / `remain_qty` | 表单 / MES 用量核对 | **新增** |
| 作业站点 `station` | 当前站点配置 | **新增** |
| 操作结果 `result` | 成功 / 失败 | **新增** |
| 失败原因 `error_info` | 异常信息 | 既有列 |
| MES 调用结果 `mes_result` | 既有 | 既有列 |
| 格口开锁结果 `lock_result` | 既有 | 既有列 |
| **格口开门时间 `door_open_ts`** | 开门时刻 | **新增**（需求方手工补充项） |
| **格口关门时间 `door_close_ts`** | 关门确认时刻 | **新增**（需求方手工补充项） |
| 「开门即清空」标记 `is_cleared` | MH 维护关门后按账面清空 | **新增** |
| 「无指令开门」标记 `is_uncommanded` | 门态监测 | **新增** |
| 流程 / 节点 `flow_id` / `node_id` | 引擎上下文 | 既有列，便于排障 |

> 需求方在「取出后的去向」栏要求记录**工单号 + 机台**：工单号记入 `product_lot_no`（领用段手工输入的领用工单批次号），机台记入 `eqp_no`。

### 3.4 记录的查看与查询

- 位置：顶栏**新增独立页签**（见 §6）。
- 默认排序：**时间倒序**（最新在前）。
- 每页 **20 条**。
- 筛选条件（**可单选、也可多选，任意组合**）：
  时间范围、物料批号、格口编号、操作人、机台号、动作类型。

### 3.5 导出

- 格式：**Excel**。
- 目的地：**本地目录 / U 盘**。
- 权限：**仅物料员与维护人员**。
- 导出范围：按当前筛选条件导出；导出行为留痕。

### 3.6 按批号追溯（全程时间线）

输入某卷焊丝批号，输出其从**入库 → 在柜 → 归还 → 被取走**的完整时间线。

- 不做按时间 / 人员的统计报表（需求方仅勾选「按批号追踪全程」）。
- 但列表页仍保留按操作人、时间范围筛选的能力。

### 3.7 保留、防篡改与留痕

- **永久保留**：记录只增不删。
- **归档**：按周期归档（建议按年分表或定期导出备份留存），**归档后不删除**。
- **防篡改**：记录不可修改 / 删除；先做应用层禁止，如需更强可另加校验列。
- **留痕**：查看、导出行为本身也写入记录表。

### 3.8 写入失败与补偿

记录写入失败**不阻断业务操作**，但必须可发现、可补偿：

1. 落故障日志；
2. 界面**告警提示**；
3. 后台**自动重试**；
4. 提供**待补偿列表**，支持人工重试。

### 3.9 特殊情形

| 情形 | 处理 |
|---|---|
| 「开门即清空」（格口无内部传感器，维护开门关门后按账面无料处理） | 记录为「已清空」（`is_cleared = 1`） |
| 计划外开门（锁具异常释锁） | 记录为无指令开门（`is_uncommanded = 1`），便于确认原因 |
| 同一格口连续多次操作 | 每次操作各记一条 |
| 记录写入失败 | 见 §3.8，不阻断业务 |

### 3.10 与其它模块的关系

| 模块 | 关系 |
|---|---|
| MES 对账界面 | **独立**，不并入；两者并存 |
| 焊丝 6 条流程 / 流程引擎 | 只在节点成功后**挂接写入**，不修改流程定义与路由 |
| 格口控制层 / 硬件层 | 只读取门态与开关时刻，不改格口状态机 |
| 控车与回充 | 动作记入本功能；`agv_move_log` 保留为控车明细 |

## 4. 应用数据库

运行时仍为**柜端 SQLite**（`requirements/versions/0.1/wire-cabinet/data/app.db`）。

**既有表**：[`app_operation_log`](../0.1/wire-cabinet/scripts/schema.sqlite.sql)
既有列：`id / ts / operator_id / flow_id / node_id / slot_no / lot_no / message / mes_result / lock_result / error_info`

**需新增列**（§3.3 标注「新增」的全部字段）：
`operator_name / operator_team / operator_role / action_type / wire_spec / eqp_no / product_lot_no / qty / remain_qty / station / result / door_open_ts / door_close_ts / is_cleared / is_uncommanded`

- 建表语句改动落在 `requirements/versions/0.1/wire-cabinet/scripts/schema.sqlite.sql`。
- **不新增服务器数据库**；「永久保留」由本地库 + 备份 + 归档满足。
- 建议为查询性能加索引：`ts`、`lot_no`、`slot_no`、`operator_id`、`eqp_no`。

## 5. 数据接口

正式 SQL 目录：`requirements/data-access-sql/sql-catalog/items/`（`sql_id` 前缀 `app.`）

| sql_id（拟） | 用途 | 操作 |
|---|---|---|
| `app.operation_log.insert` | 写入一条记录 | write |
| `app.operation_log.list_by_filter` | 按六项条件组合查询（分页，时间倒序） | read |
| `app.operation_log.list_for_export` | 按当前筛选条件取导出数据 | read |
| `app.operation_log.timeline_by_lot` | 按批号取全程时间线 | read |
| `app.operation_log.mark_*`（可选） | 留痕：查看 / 导出行为写入 | write |

- 新增条目后须同步 `requirements/data-access-sql/sql-catalog/index.yaml`。
- 本功能**不新增 MES 接口**，仅复用 0.1 已有的 MES 查询结果（操作人姓名、规格、机台等）。

## 6. 界面

- 顶栏**新增第 6 个页签「物料存取记录」**。既有 5 个：操作员 OP / 物料员 MH / 维护 MAINT / MES 对账 / 控车 AGV。
- 页签内容：筛选区（六项条件）+ 记录列表（时间倒序、每页 20 条）+ 导出按钮 + 按批号追溯入口。
- 权限：仅物料员与维护人员可进入（密码门禁）。

**顶栏空间已实测**（2026-09-22，1024×768 实机运行）：当前 5 个页签已占满顶栏——标题「焊丝发放系统 DEMO」约占 185 逻辑像素，5 个页签平分剩余宽度、彼此留白较大。**再加一个 6 字标签的页签会明显变紧**，实现前须先定其一：

- 缩短标签（如「存取记录」4 字）
- 改为图标 + 文字
- 把「MES 对账」「控车 AGV」收进「更多」菜单

不得挤压现有页签的触控尺寸。

- 全部界面遵守 [../0.1/docs/HMI界面约束.md](../0.1/docs/HMI界面约束.md)：固定 1024×768、无滚动、触控目标尺寸、字号下限、统一主题资源键。
- 涉及 `requirements/versions/0.1/wire-cabinet/src/WireCabinet.Hmi/MainWindow.xaml`。

## 7. 0.2 明确不做

- 服务器 / 集中式数据库，跨柜汇总统计
- 按时间或人员的统计报表、图表、大屏
- 记录功能并入 MES 对账界面
- 修改或删除历史记录
- 对 0.1 既有流程定义、到站门禁、控车策略的改动
- MES 新增写接口或新字段回传
