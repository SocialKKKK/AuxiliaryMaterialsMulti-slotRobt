# 0.2 版本验收清单

## 1. 验收目标

- **定位**：0.2 唯一新增需求「物料存取记录与追溯」的功能验收，不重复验收 0.1 既有能力。
- **核心**：**任一存取动作都会自动产生记录**、**记录字段完整**、**可按六项条件组合查询**、**可按批号追溯全程**、**可导出 Excel**、**写入失败不阻断业务且可补偿**。
- **原则**：**全部真实联调**，不提供 Mock；不按「全平台日志审计」标准卡 0.2。
- 需求原文与决议见 [物料存取记录-需求确认清单.md](物料存取记录-需求确认清单.md)；范围见 [需求范围.md](需求范围.md)。

## 2. 验收标准（模块级）

| 模块 | 验收标准 | 演示 |
|---|---|---|
| 记录写入 | §3 覆盖矩阵中**全部动作**均产生记录；一次「人的操作 / 有业务意义的动作」一条，开门、关门、清空是这条上的字段（口径优化 2026-10-09） | 脚本 1、2 |
| 字段完整 | [需求范围 §3.3](需求范围.md) 列出的字段**逐列非空**（该场景不适用者可为空，但不得缺列） | 脚本 1、2 抽查 |
| 门开关时间 | 业务记录（或没有业务结果时的开门记录）含 `door_open_ts` / `door_close_ts`，时间与实际操作一致；`door_close_ts` 不早于 `door_open_ts` | 脚本 2、3 |
| 查询 | 六项条件**各自单独生效**，且**可任意组合**；默认时间倒序，每页 20 条 | 脚本 4 |
| 批号追溯 | 输入批号可看到 入库 → 在柜 → 归还 → 取走 的完整时间线 | 脚本 1 |
| 导出 | 导出 **Excel** 到本地目录与 U 盘；导出内容与当前筛选一致 | 脚本 4 |
| 权限 | 物料员、维护/管理员可查看与导出；**操作员不可见** | 脚本 4 |
| 留痕 | 查看、导出行为本身也写入记录 | 脚本 4 |
| 失败补偿 | 写入失败**不阻断业务**，有告警、自动重试、待补偿列表可人工重试 | 脚本 5 |
| 保留 | 记录**只增不删**，无任何修改/删除入口；口径优化后放宽为「业务事实不可改写」——库层触发器只放行补 NULL 门时刻与更新过程派生字段 `detail` | 抽查 |
| 界面 | 顶栏第 6 页签可用；1024×768 无滚动、触控尺寸与字号达标 | 抽查 |

## 3. 记录范围覆盖矩阵

验收时逐项勾选（通过 / 未测 / 失败）：

| # | 动作 | 通过条件 |
|---|---|---|
| 1 | MH 存入可用焊丝 | 存料成功后产生 **1 条**记录，含规格、批号、格位、时间，并含该格 `door_open_ts` / `door_close_ts` |
| 2 | OP 归还旧焊丝（退料提交） | 退料提交成功后产生 1 条记录 |
| 3 | OP 领用新焊丝（领用提交） | 领用提交成功后产生 1 条记录 |
| 4 | OP 从格口取出焊丝 | **与领用合并为同一条**（决议 1 已于 2026-10-09 变更），该条含门开 / 门关时间；仅当取出后库存更新失败才另留一条 `op_take_wire` 失败记录 |
| 5 | MH 取出旧焊丝（打开单个格口） | 开锁成功后产生 **1 条**「MH 取出旧焊丝」记录（带该格被取走的批号），关门确认后把 `door_close_ts` 补进同一条 |
| 6 | MH 批量打开格口 | **逐格一条**：打开 N 格产生 N 条「MH 取出旧焊丝」，每格各自回填 `door_close_ts` |
| 7 | 维护人员试开单个格口 | 试开成功后产生 **1 条**记录，关门确认后回填 `door_close_ts` |
| 8 | AGV 控车 / 自动回充 | 下单、暂停、继续、取消、回充、返航均产生记录；**自动路径同一原因连续失败合并成 1 条**（`detail.count` / `first_ts` / `last_ts`） |
| 9 | 操作失败 | 开锁失败 / MES 报错 / 未关门 → 记录 `result = 失败` 且 `error_info` 有原因 |
| 10 | 无指令开门 | 库内无开门指令而 DI 显示释锁 → 产生记录且 `is_uncommanded = 1` |
| 11 | 「开门即清空」 | MH 开门关门后 → 开门那条记录 `is_cleared = 1` 且 `detail.cleared_lots` 列出被清批号（不再单独成条） |
| 12 | 同一格口连续多次操作 | 每次开门各 1 条，条数正确（关门是回填，不再另计） |

> 参考：[需求范围 §3.1](需求范围.md)。第 9 项失败不单独成类，而是同一动作记录的 `result = 失败`。

## 4. 必须演示的脚本

### 脚本 1：存入焊丝并追溯全程

```text
作业站已到站（真实 RCS）
→ MH 存焊丝：批号 → MES 校验 → 分配空格口 → 真开锁 → 放入 → 关门
→ 打开「物料存取记录」页签：可见 1 条存入记录，字段完整
→ 按该批号追溯：看到 入库 这一段
→ 继续走 OP 归还 / 领用 / 取出
→ 再按该批号追溯：可见 入库 → 在柜 → 归还 → 被取走 的完整时间线
```

**通过**：记录自动产生、字段非空、时间线与实际操作顺序一致。

### 脚本 2：一次存废取新产生两条记录

```text
作业站已到站
→ OP 存废取新：归还段提交 → 领用段提交 → 取出新料 → 关门
→ 记录页按操作人 + 当天时间范围筛选
→ 应见 2 条业务记录：归还 1 条、「领用并取出」1 条（领用与取出合并）
→ 两条都含 door_open_ts / door_close_ts（关门确认后回填），且与现场开门、关门时刻一致
→ 不应再出现独立的 door_open / door_close / op_take_wire 成功记录
```

**通过**：业务记录 2 条；门开关时间是这两条上的字段且正确。

### 脚本 3：维护开门、试开与无指令开门

```text
→ MH 批量打开「所有可用焊丝格口」：真开锁 N 格
→ 记录页按动作类型筛选：应产生 **N 条**「MH 取出旧焊丝」（N = 实际打开格口数），每条一个格口号
→ 每格关门后它自己那条的 `door_close_ts` 被回填（不新增记录）
→ 维护视图试开 1 格：产生 1 条试开记录
→ 现场制造一次无指令释锁（或按约定方式模拟门态突变）
→ 记录页应出现 1 条 is_uncommanded = 1 的记录
```

**通过**：批量开门条数与实际开门数一致（逐格一条）；试开留痕；无指令开门被记录且可识别。

### 脚本 4：查询、筛选组合、权限与导出

```text
→ 六个筛选条件逐个单独使用，各能正确过滤
→ 组合使用（如 时间范围 + 格口编号 + 动作类型），结果正确
→ 验证默认时间倒序、每页 20 条
→ 以操作员 OP 身份尝试进入该页签：应被拒绝或不可见
→ 以维护身份导出 Excel 到本地目录：内容与当前筛选一致
→ 导出到 U 盘：成功
→ 回到记录页：应能看到「查看」「导出」行为本身的留痕
```

**通过**：筛选正确、权限生效、导出格式与内容正确、导出与查看均有留痕。

### 脚本 5：写入失败不阻断业务并可补偿

```text
→ 按约定方式注入记录表写入失败（如临时改名 app_operation_log；须保留待补偿表可写）
→ 正常执行一次存料或领用：业务应照常完成，界面有告警提示
→ 故障恢复后触发自动重试（或人工重试）
→ 待补偿列表中出现该条失败记录，人工重试后成功补写
```

**通过**：业务未被阻断；失败可发现（告警/列表）；可重试并补写成功。

## 5. 必须覆盖的异常

每项须：**中文提示、不崩溃、可重试、有迹可查**。

| 类别 | 异常 |
|---|---|
| 查询 | 无匹配结果；时间范围起止颠倒；筛选条件全空 |
| 追溯 | 批号在记录中不存在 |
| 导出 | U 盘未插入 / 目标不可写；导出中断 |
| 写入 | 记录写入失败（业务不阻断，需告警 + 重试 + 补偿） |
| 权限 | 操作员进入页签；未通过密码门禁；会话超时 |
| 并发 | 批量开格口期间产生多条记录不丢、不串格口 |
| 数据 | 字段缺失（如无 MES 结果）；批号为空的操作仍能落库 |

## 6. 数据验收

| 项 | 内容 |
|---|---|
| 字段完整 | §3.3 全部列存在（作业站点已于 2026-10-09 从条款中删除）；该场景不适用的列允许为空，但列不得缺失 |
| 粒度正确 | 一次「人的操作 / 有业务意义的动作」一条；开门、关门、清空是这条上的字段；批量开门逐格一条 |
| 时间正确 | `ts`、`door_open_ts`、`door_close_ts` 与现场操作时刻一致；格式统一；`door_close_ts` 不早于 `door_open_ts` |
| 只增不删 | 无修改、删除入口；DB 层只允许「补齐 NULL 门时刻」与「更新失败记录 `detail`」两种 UPDATE（触发器 `trg_app_operation_log_append_only` 强制） |
| 追溯串链 | 同一批号的记录可按时间串成 入库 → 在柜 → 归还 → 取走 的完整链条 |
| 留痕 | 查看、导出行为也产生记录 |
| 存储 | 仍为柜端 SQLite；「永久保留」由备份 + 归档满足（归档后不删除） |

## 9. 兼容性验收（不影响现有功能）

本功能的硬性约束：**开启后不得影响 0.1 既有功能的使用**（见 [需求范围 §1.4](需求范围.md)）。

| # | 检查项 | 通过条件 |
|---|---|---|
| C1 | 记录写入失败**不改变流程路由** | 故障注入后执行存料 / 归还 / 领用，流程 outcome 与正常运行一致，界面无「业务失败」提示 |
| C2 | 停用记录功能后 0.1 能力完好 | 停用页签入口 + 停用写入挂接，[../0.1/验收清单.md](../0.1/验收清单.md) §5 的五条脚本仍**全部通过** |
| C3 | 记录表缺失 / 为空不影响业务 | 删除或清空 `app_operation_log` 后，0.1 业务链路照常运行，无异常弹窗 |
| C4 | 批量开格口耗时无明显变化 | 开启记录前后，批量打开全柜格口的总耗时差异在约定范围内（建议 ≤10%） |
| C5 | 不产生记录洪水 | 控车 / 回充仅在状态迁移时记录；**静置 5 分钟记录条数为 0** |
| C6 | 未新增 MES 调用 | 记录字段全部复用流程内已有 MES 查询结果，无新增 MES 请求 |
| C7 | 既有库升级安全 | `ALTER TABLE ADD COLUMN` 只加列；升级后 0.1 既有功能照常，既有数据未被改动 |

> C1 是最易出错的一条：`FlowEngine` 内既有的 DISCOEQPNO 同步挂接与之**同位置**，其失败会把 outcome 改为 `error`；记录写入不得沿用该写法。
> C4 的耗时以现场可重复的操作计时为准，演示脚本须写明测量方式。

## 10. 未通过条件（任一条即不达标）

- §3 覆盖矩阵中任一「必须记录」的动作未产生记录
- 一次业务操作产生多条或漏条（粒度错误：一次人的动作应恰好一条）
- 取出动作**未**与领用合并（违背 2026-10-09 变更后的决议 1）
- 业务记录 / 开门记录缺门开、门关时间（`door_close_ts` 早于 `door_open_ts` 同样算错）
- 六项筛选条件任一不可用，或不可组合
- 操作员可查看或导出记录（权限失效）
- 记录可被修改或删除（「只补 NULL 门时刻 / 更新 `detail`」之外的任何 UPDATE、任何 DELETE）
- **记录写入失败阻断了业务操作**（违背决议 4）
- 写入失败无告警、无重试、无待补偿列表（无法「及时找到解决办法」）
- 导出不是 Excel，或导出内容与筛选不一致
- 界面在 1024×768 下出现滚动、或触控尺寸与字号不达标
- 依赖 Mock / 模拟数据完成验收
- **记录写入失败导致业务被判定失败或被阻断**（违背 §1.4 第 1 条）
- 停用记录功能后，0.1 的五条演示脚本无法全部通过
- 控车 / 回充按轮询 tick 记录，静置时仍持续产生记录
- 为记录功能新增了 MES 调用
- 数据库升级改动了既有列或既有数据
